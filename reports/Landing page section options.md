# Stitch one tailoring object through every section

The strongest Teaching Threads landing page gives each section one physical tailoring object: a seam, a tape, a pattern envelope, a care label, an order book. Each object carries real HTML text, so the page reads as an atelier and stays clear and fast on a mid-range Android in Hubballi. The recommended combination is: **Hero A "The Seam"** (the existing clay POV sewing-machine scrub draws a stitch line that underlines the H1 and runs into the course section), **Proof B, a care-label block**, **Courses D, a size-chart spec sheet** with the envelope fronts from Courses A as headers, **Founder A, an editorial profile** with ink-duotone runway plates, **After C, a shop-front signboard**, **Visit C, a fitting-appointment card** that writes a WhatsApp message, **FAQ A, a tailor's order book**, and **Footer A, a giant wordmark with a tape-measure edge**, all set in **type system B (Instrument Serif + Instrument Sans + a mono, with Anek Kannada)**. The canvas frame-sequence scroll does **not hurt SEO** in itself. Google indexes only rendered HTML and never scrolls, so a canvas is invisible to it and simply neutral, and the prototype already keeps text in the DOM and marks the canvas `aria-hidden` ([Google: JavaScript SEO basics](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)). The real cost is performance. `prototypes/course.html` currently requests all eight 61-frame sequences (about 6.3 MB of assets) the moment the page loads, and those requests compete with the hero's LCP. That needs fixing before launch. Two client facts change the content brief. There is no student work and no testimonials, so every option below drops student photos, student counts and quotes. And the client's own course PDFs supply stronger proof than the research notes assumed: **"registered fashion designer with 15 years of industry experience," "12+ years running her own boutique in Hubli-Dharwad," and "awarded the youngest female entrepreneur by Times of India"** ([3-month course PDF](<../courses/Fashion Design Course (3 Months).pdf>)).

Options without a findable real-world precedent are marked **Original**. Every option links the technique demos or nearest analogues it builds on.

### 3. What you'll learn: the built five-stage scroll needs loading fixes, not redesign

The existing section already does the SEO basics right. Each canvas is `aria-hidden`, there is a real `<img>` with descriptive alt underneath, and the stage headings are HTML. Three changes matter. First, **stop loading every frame at page load.** The current loop creates all 61 `Image` objects for each of eight sequences straight away. Instead, start a sequence only when its section is near the viewport (IntersectionObserver with `rootMargin: "100% 0px"`), and fetch every fourth frame first so scrubbing works early. Google itself recommends viewport-triggered loading over scroll-dependent loading ([Google: Fix lazy-loaded content](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)). Second, add `prefers-reduced-motion` and `saveData` fallbacks that swap each sequence for its key still. This is the same degradation Framer's scroll-video components ship by default ([Framer: Volumen Scroll Video](https://www.framer.com/marketplace/components/volumen-scroll-video/)). Third, never let stage names exist only inside Kling frames, because text baked into video is not indexed. Optional upgrade: let Hero A's stitch line or Hero D's tape act as the stage progress indicator here, so the page has one continuous thread.

### 7. Visit the studio: remove the "where is it" fear without a map iframe

WhatsApp is the dominant business channel in India: Meta said in Q3 2023 that over 60% of Indian users message a business weekly ([Sentinel Assam](https://sentinelassam.com/business/revenue-from-click-to-message-ads-in-india-has-doubled-meta-founder-672693)). ## The canvas scroll is SEO-neutral, but its loading order is a performance bug

The direct answer: **the canvas frame sequence does not hurt SEO** as long as every word lives in HTML around it. Googlebot indexes only rendered HTML, does not scroll or interact, and discovers images only from `<img src>`, not CSS backgrounds ([Google: JavaScript SEO basics](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics); [Google Image SEO](https://developers.google.com/search/docs/appearance/google-images)). `<canvas>` is not an LCP candidate at all. The LCP element will be the H1 text or the frame-0 `<img>`, which is why that `<img>` must stay visible (not opacity 0, which is excluded) and carry `fetchpriority="high"` ([web.dev: LCP](https://web.dev/articles/lcp)). The risk is bandwidth and smoothness. All ~490 frames requested at once compete with that LCP image on throttled 4G. Scroll-time layout shifts *do* count toward CLS, so animate only `transform` and `opacity` ([web.dev: Optimize CLS](https://web.dev/articles/optimize-cls)). Keep scroll handlers to a single `drawImage` per animation frame to protect INP ([web.dev: Optimize INP](https://web.dev/articles/optimize-inp)). If frame count becomes a problem, a single all-intra MP4 (`ffmpeg -g 1`) scrubbed via `currentTime` is the main alternative ([hontran.dev](https://www.hontran.dev/blog/scroll-scrubbed-video-stutters-fix)), as is decoding with the VideoDecoder API ([kerimcharfi/frame-scroll-animation](https://github.com/kerimcharfi/frame-scroll-animation)). The current frames are about 15 KB each (61 frames ≈ 0.8–0.9 MB per sequence), which is already lean. No device benchmark exists, so test on a mid-range Android.

Structured data changed in 2025–2026. **Course Info rich results were retired** (announced 12 Jun 2025) ([Google Search Central blog](https://developers.google.com/search/blog/2025/06/simplifying-search-results)). **FAQ rich results stopped appearing on 7 May 2026** ([Google: FAQPage changelog](https://developers.google.com/search/docs/appearance/structured-data/faqpage)). The Course *list* carousel survives, but it needs three or more courses ([Google: Course list](https://developers.google.com/search/docs/appearance/structured-data/course)). Put an `["EducationalOrganization","LocalBusiness"]` + `Person` + `Course` graph in the head, with the exact address, `geo`, hours and `telephone` with the country code. **Do not self-mark star ratings** ([Google: LocalBusiness](https://developers.google.com/search/docs/appearance/structured-data/local-business)). The visible FAQ HTML is now the SEO asset, not FAQPage markup.

Correct three items carried over from the research notes. Do not use an "Student work / Runway" H2; use "Shruti's runway work". Do not use the "final runway collection" course description; use the real modules. Do not use student-runway alt text or filenames; use names like `shruti-mahajan-forest-fury-kerala-fashion-league-2016.webp`. A suggested outline is one H1 ("Fashion Designing & Tailoring Courses in Hubballi") and an H2 per section. Local ranking depends on relevance, distance and prominence, including reviews, and cannot be bought ([GBP Help: local ranking](https://support.google.com/business/answer/7091)). So the Google Business Profile, under its real-world name with no keywords ([GBP guidelines](https://support.google.com/business/answer/3038177)), matters more than any on-page trick. Use "Hubballi (Hubli)" and "Hubli-Dharwad" in the copy, since the city was renamed but both spellings persist ([Wikipedia: Hubli](https://en.wikipedia.org/wiki/Hubli)). The client PDF itself says "Hubli - Dharwad". Keep NAP identical on Justdial and Sulekha ([onecity](https://onecity.co.in/blog/local-citation-building-for-bangalore-businesses/)). For fonts, self-host WOFF2 split by `unicode-range` so English visitors never download Kannada. Preload only the hero display face, and use `size-adjust` fallbacks to limit swap shift ([web.dev: Font best practices](https://web.dev/articles/font-best-practices); [Chrome: font fallbacks](https://developer.chrome.com/blog/font-fallbacks)). Check that the Latin subset includes ₹, or add a one-glyph file as Superr does ([thesuperrco.com base.css](https://thesuperrco.com/css/base.css)). Host a static site (Astro or plain HTML) on Cloudflare Pages, which has Indian PoPs ([Cloudflare](https://blog.cloudflare.com/cloudflare-launches-in-india-with-data-centers-in-mumbai-chennai-and-new-delhi/)). A `/kn/` page needs reciprocal hreflang and must genuinely be in Kannada ([Google: hreflang](https://developers.google.com/search/docs/specialty/international/localized-versions)).

## Conclusion

Losing student work and testimonials turns out not to be a weakness. The client's own PDFs carry better evidence than a new academy's student gallery would: 15 years in the industry, a Times of India award, a boutique in Hubli-Dharwad, and Kerala Fashion League 2016. The 6-month course's Aari, boutique-management and market-visit modules are concrete differentiators that a side-by-side size chart shows honestly, without SaaS tropes. Repeating one tailoring object per section makes the page memorable, and it shifts most of the creative weight onto typography and treated stills, which are cheap to load. That leaves the Kling scrub as the single expensive moment.

Two open questions should be settled with the client before build. Should the "130+ Google ratings at 4.9" claim appear at all, given the no-testimonials rule? And what are the fees and batch timings, which three options (Courses D, Visit C, FAQ) depend on? On SEO, the 2026 retirement of FAQ and Course rich results means the page will win on local profile strength, real HTML copy and speed. Visual ambition does not cost search ranking; slow frame loading does.
